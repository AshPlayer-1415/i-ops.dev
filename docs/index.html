Paste this to Claude Code, Codex, Cursor or whatever you have open. It installs assurance, works out where it will actually find something, runs it, and tells you what it found without being allowed to tidy the answer up.

Install and run the I-Ops assurance audit for me, then report what it found.

WHAT IT IS
A Python CLI on PyPI called `assurance`. Run it with `uvx assurance audit`, or
`pipx run assurance audit` if uv is not installed. It needs no account, no API key and
no network. Do not add credentials, do not sign me in, and do not send any file from
this project anywhere.

THE PART THAT MOST PEOPLE GET WRONG
`assurance audit` reads the coding-agent session recorded FOR THE DIRECTORY IT IS RUN IN.
It looks in ~/.claude/projects and ~/.codex/sessions. If I have never run Claude Code or
Codex in this exact directory, there is no session and the command will correctly refuse.
That is not an error and not a broken install.

So before you run it, work out where it will find something:

  ls ~/.claude/projects        # one entry per project, "/" written as "-"
  ls ~/.codex/sessions         # nested by year/month/day

Each ~/.claude/projects entry is the project path with every "/" replaced by "-", so
"-Users-me-myproject" means /Users/me/myproject. Pick the directory we are working in if
it appears. If it does not appear, say so and run `uvx assurance audit --demo` instead,
which shows a sample report and needs no session at all.

THEN
1. Run the audit in a directory that has a session.
2. Show me its output verbatim. Do not summarise a finding away and do not reword it.
3. Do not fix anything you see in the report unless I ask.
4. If it reports that something was not checked, tell me plainly which thing.

WHAT GOOD OUTPUT LOOKS LIKE
A line naming the session and how long it ran, then a short list of what was and was not
covered. For example: "No prompt typed by the person was found to check the outcome
against." That is the tool telling you it could not verify the goal, which is information,
not a failure.

Install

There is nothing to install permanently. uvx fetches it, runs it and throws it away.

uvx assurance audit

That needs uv. Without it, pipx run assurance audit does the same thing, and pip install assurance installs it properly if you would rather keep it.

No account, no API key and no network. Everything it reads is already on your machine and nothing leaves it.

Where to run it

Assurance reads the coding‑agent session recorded for the directory you are in. It looks in two places that your agent already writes to:

AgentWhere its sessions live
Claude Code~/.claude/projects
Codex~/.codex/sessions

This is the mistake that loses most people on their first try. You run uvx assurance audit in your home directory, or in a project you have only ever opened in an editor, and it says there is no session. The command is not broken and the install is fine. There is genuinely nothing there to read, because you have never run an agent in that folder.

It happens because the install command is the thing people copy, and the first place anyone pastes a command is wherever their terminal happens to be.

Find a folder that will work

Every entry in ~/.claude/projects is a project path with each / written as -, so -Users-you-myapp is /Users/you/myapp.

ls ~/.claude/projects

cd into one of those and run the audit there.

Or skip the hunt entirely

If you just want to see what the output looks like before committing to any of this, there is a sample report that needs no session at all.

uvx assurance audit --demo

Your first report

Run in a folder with a real session, the output is short on purpose:

Codex session 01a1e80b — 3h 34 min in /Users/you/project No prompt typed by the person was found to check the outcome against. Every shell command was classified. Also in the transcript: 9 assistant turns, 4 user turns, 102 bookkeeping records. Not read: 0 lines.

The bolded line is the point of the tool. It is not an error. It is assurance telling you that it could not find a stated goal to check the result against, so nobody, including it, can say whether the run did what you wanted.

That is the whole idea: the thing that did the work does not get to be the thing that says it went well.

Signing in

Optional, and it changes nothing about the checks. An account never gates a check and never will: the CLI has no account, no API key and no network, and that is the point of it rather than a limitation.

What an account does is give us a way to reach you when a check you asked for ships. Sign in with Google or GitHub if you want that. The welcome email carries a link that deletes the record and every sign‑in event attached to it, in one click, if you change your mind.

The commands

audit is the one to start with. The rest answer narrower questions and each takes --help.

CommandWhat it answers
auditWhat the session in this folder did, and what it skipped
hookRun the audit automatically after every Claude Code turn
couplingWhat usually changes with what you just changed, from git history
reachWhat a change to a file or folder reaches
clearanceWhether the person who asked is cleared for every owner it reaches
depsWhat a Python install is about to execute, read without executing it
budgetWhere a run's budget went, and where it looped going nowhere
pinPin MCP tool definitions and detect supply-chain drift
driftDetect a shift in a binary outcome stream
serveA local endpoint any agent can send traces to

Troubleshooting

“no Claude Code or Codex session recorded for …”

Working as intended. You are in a folder where you have never run one of those agents. Read Where to run it, or run with --demo to see a sample.

uvx: command not found

You do not have uv. Use pipx run assurance audit, or install uv from docs.astral.sh/uv.

Odd characters, or a crash, on Windows

Piped output on Windows uses the locale code page rather than UTF‑8. If you see a crash or a row of question marks, report it with the command you ran: that is a bug on our side and we want it.

Something else

Open an issue at github.com/i‑ops‑hq/assurance, or reply to any email from us. If an agent has ever told you a job was done when it was not, that is the thing we most want to hear about: it is where the checks come from.
