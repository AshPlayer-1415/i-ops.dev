/   assurance

Your agent says it is done. This tells you what it did not check.

One command, in a folder where you have used a coding agent. It reads that session and reports what the run covered and what it quietly skipped. Nothing is sent anywhere. 

uvx assurance audit

One more, for when the question is what a change reaches rather than what it tested: uvx assurance coupling reads your own git history and says what usually travels with the files you touched, and how much more often than chance. No configuration, and nothing leaves the machine.

Works with what you already run

It reads the session your agent already writes. There is nothing to configure and no integration to install.

  • Claude Code — reads ~/.claude/projects. A hook can run the audit after every turn: assurance hook install.
  • Codex — reads ~/.codex/sessions.
  • Any agent, via MCP — an MCP server on the official registry, read‑only by construction.
  • CI — a GitHub Action that fails the build when a check does not pass.

Is it reliable?

0% error rate across 186,699 plugin loads. Zero failed installs, zero command errors. That is Anthropic’s figure from their plugin marketplace, over the last 90 days, not ours. For a tool that sells verification, the most useful number is one somebody else recorded.

Our own number, labelled as ours: 962 plugin installs. We used to print a download count here too and we have stopped, because our own measurement said it was machine traffic rather than adoption — seven packages growing within 3.4% of each other is one process pulling a dependency tree, not seven choices. We would rather show you one number we trust than two we have to qualify.

Where does my code go?

Nowhere. assurance makes no network request of any kind. Every check runs on your machine, against your files, with no key and no login. That does not change if you sign in — signing in is for the conversation, not the tool. If we ever add something that sends data somewhere, it will be a command you choose to run and it will say what it sends.

Verify that rather than trusting it. There is no HTTP client anywhere in the install, dependencies included: 

pip download assurance -d a && cd a && for w in *.whl; do unzip -oq "$w" -d src; done
grep -rn "urlopen\|requests\.\|httpx\.\|aiohttp" src --include='*.py'

No output. The unzip step is the point — a wheel is a zip, so grepping the downloaded files directly finds nothing whether or not there is anything to find.

Can you get out?

Apache‑2.0, and removing it is one step: uvx leaves nothing behind at all, and an installed copy goes with pip uninstall assurance. The hook, if you installed it, comes out with assurance hook remove. There is no account to close, because you never needed one to run a check.

Source at github.com/i‑ops‑hq/assurance. Read it, fork it, or copy the parts you want.

What it costs

Nothing, and there is no paid tier to upgrade to today. If that changes, the checks that run on your machine stay free — that is the part we are not willing to make conditional.

One thing we are asking for

A batch job reports success while records are missing, truncated, or quietly replaced by a retry under a new ID. The question worth answering is not did the job succeed but did every record you sent actually come back.

That check does not exist yet, and this is how it gets built. If you run batch inference on Bedrock, OpenAI or Anthropic and have ever found out late that a run was short, send us the shape of the failure. A research team did exactly that — eight failures from one production run. The first of them are already checks you can run; the rest are being built in the order they asked for.

Sign in, describe the failure, and we will tell you whether it is already covered or build the check.
