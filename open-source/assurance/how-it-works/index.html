What it actually prints.

Eight screens in the order you meet them, from a command you can run in the next minute to a gate in your pipeline.

Every block below is real output, captured on 20 November 2026 from assurance 0.1.40 installed from PyPI. None of it is drawn, edited or reconstructed. The first one runs against a sample session that ships with the tool, so you can reproduce it exactly; the rest came from real projects on one machine, and yours will name your files instead. Where a block is not a capture, the caption says so.

02

The line that matters is four lines down.

The agent was asked to fix a rounding bug and finished by saying the totals were correct. The report does not argue with that. It says when the test last ran.

“pytest -q tests/test_invoice.py: did not run after the last edit to src/billing/rates.py (07:09); it last failed at 07:08, before that.”

The suite the work depended on last ran one minute before the final edit, and failed. Everything downstream — the review, the merge, the deploy — saw a finished task.

04

After every turn, without being asked.

A hook runs the audit when the agent stops. It shows you the exact change to your settings file, backs the file up, and asks before writing.

$ uvx assurance hook install --scope local

local settings: /home/you/my-app/.claude/settings.local.json
--- (no file)
+++ settings.local.json (after)
@@ -0,0 +1,14 @@
+{
+  "hooks": {
+    "Stop": [
+      { "hooks": [ { "type": "command",
+          "command": "uvx --offline assurance@0.1.40 audit --hook --nudge" } ] }
+    ]
+  }
+}
Not written. Rerun with --yes to write it (this is not an interactive terminal,
so nothing was asked).

Real output · a fresh install into a throwaway project, 0.1.40. The last two lines are the point: in a non-interactive shell it refuses to write rather than install quietly.

05

Three lines: the finding, the evidence, the fix.

This is what appears after a turn when something is unverified. It states what it found, when, and the one command that would settle it.

Assurance audit of this session (stop and check): committed on main at 23:23
and whether a test or check passed after the last edit to scripts/gen_usecases.py
(19:01) is unconfirmed. Before you go further, run the project's tests or checks
for what you changed, without piping the test command into another (or with
`set -o pipefail`) so its result is visible, or say plainly why they cannot be
run here.

Real notice · from a real session on 20 November 2026, unedited. The hook always exits 0, so it never blocks the agent and never stops your work.

08

And the same check as a gate.

The exit codes are the published ones, so it drops into a pipeline without a wrapper.

- uses: i-ops-hq/assurance@v1
  with:
    fail-on: finding

# exit 0  checked, found nothing
# exit 1  something to look at, including something it could not check
# exit 2  could not run

Workflow fragment · not a capture. The three exit codes are from the published table in the project README.

Run the first one.

It needs no account, makes no network request, and reads only the session your agent already wrote. 

uvx assurance audit --demo

Apache‑2.0, source at github.com/i‑ops‑hq/assurance. Nothing, and there is no paid tier to upgrade to today. If that changes, the checks that run on your machine stay free — that is the part we are not willing to make conditional.
